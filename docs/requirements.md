# 嵌入式设备交互式 Markdown 调试工作台

## 需求规格与大模型开发执行手册

版本：0.1（需求基线草案）  
日期：2026-10-21  
暂定项目代号：MDTUI  
文档用途：产品设计、架构设计、开发任务拆分、自动化测试与交付验收。

> 本文中的用户事实来自需求沟通；技术方案和协议细节是为启动开发提出的默认设计，尚不代表用户已确认所有取舍。开发者不得将默认假设表述为已验证的设备能力。

## 1. 背景与目标

### 1.1 已确认的原始需求

- 用户有一台运行 Linux 的嵌入式设备。
- 用户在电脑上通过 SSH 工具连接设备，进入设备的 Linux shell。
- 设备上已有许多调试命令，命令较分散。
- 部分命令已经支持 Markdown 输出，其他命令可以逐步改造成 Markdown 输出。
- 用户目前能够通过管道渲染原始 Markdown。
- 某些命令存在业务关联：需要先执行命令获取信息，再根据结果决定下一条命令及其参数。
- 用户希望用一种简单、支持流式展示、交互和刷新的 Markdown 扩展，把命令组织成具有整体性的 TUI。

### 1.2 要解决的问题

当前操作依赖操作者记忆命令、寻找标识、复制参数、反复切换输出和人工关联信息。已有 Markdown 输出解决了单次结果的可读性，但没有解决命令导航、对象选择、上下文传递、局部刷新和持续观察。

### 1.3 产品目标

提供一个运行在设备上的常驻终端程序。用户通过 SSH 启动该程序，即可使用页面文件组织现有命令，完成对象选择、关联查询、周期刷新、流式诊断和上下文保留。

成功标准：用户无需修改工作台源代码，编写一份页面文件并适配必要的数据标识，即可将一组真实调试命令组合成可用界面。

### 1.4 典型使用流程

1. 用户通过 SSH 登录设备。
2. 执行 `mdtui network.md`。
3. 页面加载设备或接口列表。
4. 用户使用方向键选中对象并按 Enter 确认。
5. 详情和统计面板自动查询该对象。
6. 统计按设定周期更新；用户可手动刷新。
7. 用户触发诊断动作，在日志面板查看持续输出。
8. 用户退出工作台，返回可正常使用的 shell。

## 4. 系统职责与总体结构

```text
SSH 终端
  ↕ 键盘 / 光标与文本更新
终端适配与渲染层
  ↕ 用户事件 / 视图模型
状态仓库 + 事件循环
  ├─ 页面解析与校验
  ├─ 依赖解析与调度
  └─ 进程执行与输出解析
          ↕ stdin / stdout / stderr / 退出状态
       现有调试命令或适配器
```

职责边界：

- 页面文件声明布局、数据来源、动作与数据引用。
- 调试命令负责业务查询或操作，不负责管理整个 TUI。
- 适配器将旧命令输出转成可选择的对象数据，保持旧命令可独立使用。
- 工作台负责生命周期、并发、选择状态、局部更新与终端恢复。
- SSH 负责连接和终端传输；工作台无需自行处理 SSH 协议。

## 5. 页面语言 MDTUI Markdown v0.1

### 5.1 设计原则

1. 普通 Markdown 可直接显示；仅保留的扩展块具有执行语义。
2. 配置使用少量声明式字段，禁止任意表达式求值。
3. 依赖通过明确引用建立，不解析人类显示文案推断参数。
4. 先校验整份页面，再启动任何命令；配置错误不能导致部分命令已执行。
5. 页面声明具有执行能力，必须来自操作者信任的本地来源。命令输出始终作为内容解析，不递归执行其中的页面声明。

### 5.2 扩展块边界

形式：起始行 `:::mdtui TYPE`，结束行 `:::`，两者必须独占一行并位于第 1 列。内部为受限 YAML 映射。

支持的 TYPE：`page`、`panel`、`input`、`action`。

解析器必须识别 Markdown fenced code block；代码块中的扩展示例不执行。保留扩展不允许嵌套；未闭合块视为页面错误。其他 `:::` 文本不获得执行语义。禁止 YAML 自定义标签、重复键、合并键和别名，限制嵌套深度为 8。

兼容性定义：本语言保留普通 Markdown 的内容用途，但保留了上述扩展标记，因此不是对所有历史文本都零冲突的严格超集。需要原样展示扩展语法时使用 fenced code block。不支持本语言的渲染器可能显示原始配置；V1 不承诺美观降级。

### 5.3 页面声明

一页恰好一个 page 块，必须位于其他扩展块之前。

```text
:::mdtui page
version: 1
id: network
title: 网络调试
layout: master-detail
sidebar: interfaces
max_parallel: 2
:::
```

字段规则：

- `version`：必填，只接受整数 1。
- `id`：必填；全局标识使用 `[A-Za-z][A-Za-z0-9_-]{0,63}`。
- `title`：可选，默认使用页面 ID。
- `layout`：`stack`、`master-detail` 或 `workspace`，默认 `stack`。
- `sidebar`：主从布局必填，必须引用一个 panel ID。
- `parent`：可选，子页声明父页面中触发跳转的 panel ID；声明后才可使用 `{ref: "parent.selected.id"}`。
- `max_parallel`：1～8，默认 2，超过范围报错。
- 页面最多 16 个 panel、16 个 input、32 个 action；文件最大 1 MiB。

所有扩展块 ID 共享命名空间，不得重复。未知字段和未知类型均报错，避免拼写错误被静默忽略。

### 5.4 面板声明

```text
:::mdtui panel
id: detail
title: 接口详情
mode: snapshot
format: markdown
exec: ["net-debug", "show", "--name", {ref: "interfaces.selected.id"}]
timeout: 5s
:::
```

| 字段 | 取值与默认行为 |
|---|---|
| id | 必填，全局唯一 |
| title | 默认 ID |
| mode | `snapshot` 或 `stream`，默认 snapshot |
| format | `markdown`、`text`、`items-json`，默认 markdown |
| open | 可选，仅 `items-json` snapshot 可用；相对路径字符串，或选项 ID 到相对路径的映射 |
| exec | 非空参数数组；可执行文件只能是字面量字符串 |
| refresh | 仅 snapshot 可用，完成后等待指定时长再次执行；默认关闭，最小 250ms |
| timeout | snapshot 默认 5s；stream 默认 0（无限）；0 仅 stream 可用 |
| autostart | 默认 true；false 的面板仍声明命令，但等待动作触发 |
| on_focus | 可选；items-json 列表的光标移动到某一项时触发的 action ID |
| on_select | 可选；items-json 列表确认选择变化时触发的 action ID；不能与 open 同时使用 |

`exec` 参数只能是字符串或只有 `ref` 一个键的映射。禁止隐式将数字、布尔值转换成参数；需要数字参数时显式使用字符串。

`items-json` 仅支持 snapshot。其他组合超出规范时直接报错。

`open` 让列表选中项进入全屏子页。它可以是一个相对路径，也可以把选项 ID 映射到不同相对路径，让不同选项打开不同子页；未映射的选项不会跳转。子页可继续声明 `open`，最多 8 层；`mdtui check` 会跟随所有映射目标，按绝对路径检测循环、父子声明不一致和深度超限。

`on_focus` 和 `on_select` 引用一个 action ID。列表获得焦点后，光标移动到新的选项时触发 `on_focus`；页面初始加载时，聚焦列表的首个光标项也会触发一次。列表按 Enter 真正改变选中值时触发 `on_select`。刷新本身不触发；只有光标所在项的 ID 发生变化时才再次触发 `on_focus`。自动触发动作不能设置 `confirm`；两个事件都只能用于 items-json 面板，`on_select` 不能与 `open` 同时使用。

### 5.5 引用与依赖

支持四类引用：

- `<panel-id>.selected.id`：可选列表当前确认对象的稳定 ID。
- `<panel-id>.cursor.id`：可选列表当前光标所在项的 ID，不要求按 Enter 确认。
- `parent.selected.id`：父页面中触发当前子页的列表当前选中 ID；仅子页声明 `parent` 后可用。
- `<input-id>.value`：文本输入控件当前提交的值。

引用必须占据整个参数，不支持字符串内插、点路径扩展、算术运算、命令替换或 shell 求值。

引用缺失时面板进入 `blocked`，显示“请选择对象”或“请填写参数”，不启动进程。所有引用就绪后，autostart 面板自动执行。依赖更新必须递增面板 generation，旧 generation 的任何结果均不能覆盖新状态。

列表只能引用其他列表已选择的 ID，依赖图必须无环。直接或间接依赖自己均报错。下游面板依赖变化时清除其旧选择并立即使更下游引用失效，防止跨对象复用旧上下文。

### 5.6 输入声明

```text
:::mdtui input
id: filter
label: 过滤关键字
default: ""
required: false
max_length: 128
:::
```

V1 只支持单行文本。`max_length` 按 Unicode 码点计数，范围 1～4096，默认 256。编辑中值和已提交值分开；Enter 提交并触发依赖更新，Esc 放弃本次编辑。required 为 true 时空值属于缺失依赖。V1 不将其用于密码输入。

### 5.7 动作声明

动作仅允许两种互斥形式：刷新既有面板，或运行目标面板声明的命令。

```text
:::mdtui action
id: refresh_details
label: 刷新详情
key: r
refresh: [detail, counters]
:::

:::mdtui action
id: diagnose
label: 运行诊断
key: d
run: diagnostic
confirm: "对当前接口启动诊断？"
:::
```

`refresh` 只能引用 snapshot 面板；`run` 可引用任意 panel，通常用于 autostart 为 false 的面板。动作不创建新的隐式执行环境。目标依赖未满足时显示禁用原因。一个刷新动作含多个目标时按并发预算调度，不承诺各目标同时完成。

`confirm` 为可选的非空字符串；存在时弹出确认框，展示最终参数预览，默认选中取消。页面作者应为修改设备状态的操作配置确认。V1 不承诺自动判断某个命令是否有副作用。

快捷键可省略，此时仍可从动作菜单触发。重复快捷键、保留快捷键报错。V1 动作键限定为单个小写 ASCII 字母，排除保留的 q；输入框编辑时动作键不生效。

### 5.8 普通 Markdown 的摆放

扩展块以外的 Markdown 按源文件顺序合并为页面说明区，位于面板区上方；不作为可执行指令。声明顺序决定面板顺序、输入顺序和动作菜单顺序。页面说明区最多占终端可用高度的 25%，超过时可独立滚动。V1 不把 Markdown 源文件顺序解释为任意布局树。

## 7. 命令输出契约

### 7.1 通用进程契约

- stdout 为内容，stderr 为诊断，两者分别采集，不承诺跨流严格时间顺序。
- 查询和日志进程的 stdin 默认接 `/dev/null`，防止意外抢占键盘输入。
- 默认不分配子进程 PTY；命令应提供不依赖 isatty 的输出方式。
- 进程继承当前用户和环境，工作目录固定为页面所在目录，不隐式执行提权。
- `exec[0]` 含路径分隔符时按工作目录解析；否则使用启动时继承的 PATH 查找。
- 参数直接传给进程 API，不经 `/bin/sh -c`。需要管道时使用页面作者维护的包装脚本；不得自动将参数数组转成 shell 文本。
- 退出码 0 表示成功；其他退出码在面板标为失败，显示可查看的 stderr 摘要。

### 7.2 Markdown 和纯文本

`markdown` 和 `text` 不需要命令增加额外封装。静态 Markdown 最低支持标题、段落、列表、引用、强调、代码块、链接及管道表格。链接显示文本和可查看地址，V1 不启动浏览器。

不支持图片和 HTML 执行；显示替代文本或原始文本。表格允许横向滚动，不能因宽表覆盖相邻面板。

输出中的终端控制序列必须过滤，特别是光标控制、OSC 剪贴板和标题指令；不能直接透传不受信任的 escape 字节到终端。UTF-8 错误使用替代字符显示。

### 7.3 可选列表 items-json v1

stdout 必须是一个完整 JSON 对象，不得混入进度文本；进度写入 stderr。

```json
{
  "version": 1,
  "items": [
    {"id": "eth0", "label": "以太网接口 0", "description": "UP · 192.168.1.10"},
    {"id": "wlan0", "label": "无线接口", "description": "DOWN"}
  ]
}
```

- version 必须为 1；items 必须是数组，最多 10000 项。
- 每项 id 为非空字符串，最长 256 个 Unicode 码点，不得重复或含控制字符。它是业务标识，不受页面 ID 的 ASCII 规则限制。
- label 为必填字符串，description 可选；都作为纯文本显示。
- V1 拒绝未知字段，协议需要扩展时必须明确修订规范和兼容策略。
- 首次加载默认不确认任何对象；光标可位于第一行，但只有 Enter 才提交选择。
- 刷新后按 ID 保留确认选择；对象仍存在则不重复触发下游查询。
- 选中对象消失时清除选择，取消其下游任务，并将下游置为 blocked。
- 非法 JSON、重复 ID 或协议版本错误视为本次刷新失败，保留上一份有效列表并标记过期。

结构化列表是为了可靠传递业务标识，不要求所有 Markdown 输出都改为 JSON。旧命令可以通过单独的适配器提供列表。

## 8. 状态、刷新与并发模型

### 8.1 状态分类

- 页面定义：解析后不可变。
- 用户状态：确认选择、输入提交值、编辑草稿、焦点、滚动位置。
- 面板数据：最近成功内容、当前流式缓冲区、数据来源 generation。
- 执行状态：请求 ID、generation、排队/执行/成功/失败、时间及取消原因。

状态只由单一事件循环提交；进程与解析任务通过消息通知，不直接修改 UI。

### 8.2 面板状态

`idle`（等待触发）、`blocked`（依赖不足）、`queued`、`running`、`ready`、`error`、`cancelled`。

数据是否过期是独立标志。刷新开始保留旧内容并显示加载状态；同一对象刷新失败时保留最近成功内容并明确标记过期。对象变化后不得把上一对象内容当成新对象内容；V1 清空内容并显示新对象加载提示。

### 8.3 请求与取消

- 每次执行具有唯一 request ID；每次依赖变化递增 generation。
- 接收结果时同时校验目标、request ID 和 generation。
- 同一 panel 最多一个正在运行的进程。
- 同一对象的重复刷新合并为最多一次后续执行。
- 依赖变化时取消旧任务，清除旧排队请求，只保留最新上下文。
- 取消先向进程组发送 SIGTERM，等待最多 1 秒后发送 SIGKILL，并回收子进程。
- 命令不得自行 daemonize；主动脱离进程组的进程不在 V1 完整清理保证内。
- 禁止自动重试 run 动作，避免重复执行有副作用的操作。

### 8.4 周期任务

refresh 表示“本次完成后等待 N 秒”，不是固定频率重叠执行。手动刷新完成后重新计算周期。查询失败后仍按周期重试并显示错误；不隐藏连续失败次数。

并发上限对查询和流式命令共同生效。V1 允许同时运行至多一个 stream，且启动 stream 时必须保证至少保留一个查询槽位；max_parallel 为 1 时拒绝启动 stream 并提示原因。排队使用 FIFO；同面板请求合并，队列容量受面板数限制。

退出工作台必须取消所有排队任务和运行中的子进程，不再触发定时器。

## 9. 流式输出语义

明确区分三种输入：

1. 页面定义文件：V1 完整读取并校验，不支持边接收页面边执行命令。
2. snapshot 命令：完整输出经校验后替换面板；V1 不要求未完成结果的渐进预览。
3. stream 命令：随输出增量展示，进程结束后保留已收到内容。

stream 的 Markdown 在未闭合代码块、列表和最后一行处允许暂时显示预览，后续到达时可重排；不承诺任意 Markdown 前缀都有稳定 AST。必须正确处理多字节字符跨读取边界，不能把半个 UTF-8 字符提前替换。

默认最多每 100ms 合并一次 UI 内容更新。禁止收到每一个字节就重绘全部界面。流式渲染应在有界保留窗口上运行，不能随累计输出无限增加内存和解析耗时。

流式缓冲区默认同时受 2 MiB 和 10000 行限制，先达到者生效；超限丢弃最旧完整行并显示丢弃计数。单行最长 64 KiB，超出截断并标记。Markdown 窗口截断时允许重置块状态，并显示截断提示，保证可读性优先于完整文档语义。

暂停跟随仅停止自动滚动，不停止读取进程输出。End 恢复跟随。Ctrl+C 在活动 stream 面板中取消该命令；工作台正常退出使用 q。

## 10. 终端交互与布局

### 10.1 基础键位

| 键位 | 行为 |
|---|---|
| Tab / Shift+Tab | 切换可聚焦区域 |
| ↑ / ↓ | 列表移动光标，或内容滚动 |
| Enter | 提交列表选择、输入或菜单动作 |
| Esc | 关闭弹窗、取消输入草稿 |
| PageUp / PageDown | 内容分页滚动 |
| Home / End | 到顶部/底部；流式面板 End 恢复跟随 |
| ← / → | 非输入状态下横向滚动宽表或长代码行 |
| F2 | 打开动作菜单 |
| ? | 非输入状态下显示帮助 |
| Ctrl+C | 取消当前面板任务；无任务时提示使用 q 退出 |
| q | 非输入状态下退出工作台 |

弹窗优先处理输入。外部 SIGINT/SIGTERM 与终端按键分开处理：外部信号触发有序关闭。

### 10.2 布局规则

- 顶部为页面标题和说明区，底部为状态与快捷键提示。
- 输入控件构成可聚焦的参数区。
- stack 按声明顺序纵向排列面板。
- master-detail 在宽度至少 100 列时左侧显示 sidebar，右侧纵向排列其他面板；侧栏宽度为可用宽度的 30%，最少 24 列。
- 宽度不足 100 列时自动退化为 stack，不改变用户选择。
- 高度不足以同时展示全部面板时只显示当前活动面板内容，通过 Tab 切换，并显示面板索引。
- 小于 60×16 时显示尺寸不足提示；仍允许退出，不能输出越界或崩溃。
- 支持窗口 resize，不重新执行命令，不重置用户输入。
- 中文、宽字符、组合字符的显示宽度按终端单元格计算，不能按字节数或简单字符串长度布局。
- 颜色不能作为状态的唯一标识；提供无颜色模式。
- 子页全屏显示；进入时暂停父页调度并保留父页选择、滚动和焦点，返回时恢复。子页内 `Esc` 或 `q` 返回，根页 `q` 退出。

### 10.3 终端生命周期

进入 alternate screen 与 raw input 前保存终端状态。正常退出、执行错误、可恢复 panic 和可处理信号都应恢复光标、屏幕模式和输入设置。SIGKILL 等不可捕获终止不承诺自动恢复，文档提供 shell 恢复方法。

## 11. CLI 与错误处理

```text
mdtui PAGE.md
mdtui check PAGE.md
mdtui --version
mdtui --help
```

- `check` 只解析并校验文件、引用、依赖、配置边界，不启动任何子进程，也不运行命令探测。
- 普通启动必须具备可交互终端；没有 TTY 时清楚报错并建议使用 check，V1 不提供管道启动工作台。
- CLI 提供 `--no-color` 与显式 `--log-file PATH`。
- 退出码：0 为正常退出/校验通过；2 为页面或参数错误；3 为终端初始化错误；1 为其他启动或内部错误。面板命令失败本身不改变工作台正常退出码。
- 页面错误至少包含文件、行号、字段路径和修复建议。
- 单条命令失败时提供可查看的错误详情：程序名、退出码、时间、stderr 截断内容；不自动写入持久日志。
- 调试日志默认关闭；启用后默认只记录 ID、耗时和状态，不记录完整参数、stdout 或环境变量。
- stdin 管道渲染模式不是本工作台 V1 的职责；用户已有渲染管道可以继续独立使用。

## 12. 非功能要求与初始预算

以下为工程起点，需在参考开发机和实际设备分别记录结果。设备未提供前只验收参考环境，不能据此宣称实际设备性能达标。

| 项目 | 初始验收目标 |
|---|---|
| 输入响应 | 参考环境模拟命令持续输出时，按键到下一帧 p95 ≤100ms |
| 流式首屏 | 从子进程 flush 到可见内容 p95 ≤200ms，不包含命令自身缓冲时间 |
| 空闲 CPU | 无查询、无新增输出时，参考环境平均占用 ≤单核 1% |
| 内存 | 8 个面板、默认缓存额度、运行 30 分钟，工作台 RSS ≤64 MiB，不含子进程 |
| 退出时间 | 正常子进程场景 2 秒内完成清理和终端恢复 |
| 耐久性 | 高频输出运行 30 分钟无单调持续内存增长、无无界队列 |
| 单份快照 | stdout 最大 4 MiB，超过则终止该次执行并报错 |
| stderr | 每个面板保留最近 64 KiB，显示截断标记 |
| 构建 | 固定依赖版本，提供可重复的构建命令和版本信息 |

高吞吐进程可能受到管道背压；读取、限额与渲染不得共享阻塞 UI 的路径。持续输出超过处理预算时允许按规范丢弃已读取的旧日志，不能建立无界消息队列。

## 13. 建议实现结构

默认采用 Go。允许开发者经设备兼容性评估后提出替代方案，但不得在未说明影响的情况下换成需要浏览器或额外解释器的架构。

建议模块：

```text
cmd/mdtui/             CLI 与启动
internal/document/     Markdown 扩展提取、YAML 解析、错误定位
internal/schema/       类型、校验、引用与依赖图
internal/state/        状态仓库与事件定义
internal/scheduler/    队列、刷新、generation、取消
internal/runner/       进程组、输出采集、超时与限额
internal/content/      Markdown、文本、items-json 解析
internal/tui/          布局、焦点、组件、终端生命周期
examples/              页面与模拟命令
docs/                  用户、作者、适配器与构建文档
tests/integration/     模拟进程和 PTY 集成验收
```

选型时评估维护状态、许可证、交叉编译、中文宽度、终端恢复与 Markdown 表格能力。使用成熟的 TUI、Markdown 和 YAML 库，不要求从零重写这些通用能力。具体库及版本由实施时验证后记录在架构决策文档中，本文不指定未经验证的版本号。

调度器应通过时钟和 runner 接口实现可测试性。纯状态转换不依赖真实终端。运行器和 TUI 集成必须用实际子进程及 PTY 验证，不能全部用 mock 替代。
